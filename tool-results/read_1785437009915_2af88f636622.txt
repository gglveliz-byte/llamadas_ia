     1→     1→PLATAFORMA SAAS DE AGENTE DE VOZ IA
     2→     2→
     3→     3→## 1. VISIÓN GENERAL
     4→     4→
     5→     5→Construye una plataforma SaaS multiinquilino de agentes de voz con IA. El dueño del SaaS (admin) paga la cuenta maestra de Twilio. Cada cliente registrado obtiene una subcuenta de Twilio, compra números telefónicos desde el panel, y al recibir llamadas, la IA (Gemini) contesta, conversa en lenguaje natural, y ejecuta herramientas (agendar citas, consultar disponibilidad, etc.).
     6→     6→
     7→     7→**Modelo de negocio**: Recargas de saldo. El sistema debita por minuto (o por segundo, configurable por admin) de procesamiento de llamadas. Pagos procesados por **Whop.com**.
     8→     8→
     9→     9→**El Cerebro**: Gemini 3.1 Flash Live (streaming bidireccional de audio + function calling síncrono).
    10→    10→
    11→    11→**El Conector**: Twilio con `<Connect><Stream>` (WebSocket bidireccional).
    12→    12→
    13→    13→**El Frontend**: Next.js 14+ con detección de dispositivo (Desktop/Móvil), estilos inspirados en WhatsApp Web (Light/Dark).
    14→    14→
    15→    15→**Idioma de la plataforma**: Español. **Idioma de la IA en llamadas**: Configurable por cada negocio (español, inglés, portugués, francés, etc.).

    19→    19→## 2. STACK TECNOLÓGICO OBLIGATORIO
    20→    20→
    21→    21→| Capa | Tecnología |
    22→    22→|------|-----------|
    23→    23→| Frontend (Dashboard) | Next.js 14+ (App Router) + React + Tailwind CSS |
    24→    24→| Lenguaje | TypeScript en todo el proyecto |
    25→    25→| Backend ligero (CRUD, auth) | Next.js API Routes |
    26→    26→| Backend tiempo real (voz, SSE) | Express.js dedicado |
    27→    27→| Base de datos | PostgreSQL + extensión `pgvector` |
    28→    28→| Cache | Redis (`ioredis`) |
    29→    29→| Almacenamiento audio | Cloudflare R2 (S3 compatible) |
    30→    30→| LLM / Voz | Google Gemini 3.1 Flash Live (`@google/genai`) |
    31→    31→| Embeddings (RAG) | `gemini-embedding-001` (768 dimensiones) |
    32→    32→| Telefonía | Twilio (REST + TwiML + `<Connect><Stream>`) |
    33→    33→| Pagos | Whop.com (`@whop/sdk`) |
    34→    34→| Logging | Pino (JSON, no-bloqueante) |
    35→    35→| Transcodificación audio | `fluent-ffmpeg` + paquete `g711` |
    36→    36→| Email | Nodemailer (Gmail App Password) |
    37→    37→| Despliegue | Render.com (Web Services) |

   359→   359→## 5. SISTEMA DE BILLING (Whop + Wallet)
   360→   360→
   361→   361→### 5.1 Flujo de Recarga
   362→   362→
   363→   363→1. El cliente va a `/recargas` en su dashboard.
   364→   364→2. Ve los paquetes configurados por el admin (tabla `recharge_packages`).
   365→   365→3. Selecciona un paquete → se genera un **checkout link de Whop** con `metadata: { user_id, package_id }`.
   366→   366→4. El cliente paga en Whop.
   367→   367→5. Whop envía webhook `payment.succeeded` a `POST /api/whop/webhook`.
   368→   368→
   369→   369→### 5.2 Webhook de Whop (Next.js API Route)
   370→   370→
   371→   371→```typescript
   372→   372→// /frontend-next/src/app/api/whop/webhook/route.ts
   373→   373→import { Whop } from '@whop/sdk';
   374→   374→
   375→   375→const whopsdk = new Whop({
   376→   376→    apiKey: process.env.WHOP_API_KEY!,
   377→   377→    webhookKey: btoa(process.env.WHOP_WEBHOOK_SECRET || ''),
   378→   378→});
   379→   379→
   380→   380→export async function POST(request: Request): Promise<Response> {
   381→   381→    const body = await request.text();
   382→   382→    const headers = Object.fromEntries(request.headers);
   383→   383→    
   384→   384→    // Verifica firma automáticamente. Lanza excepción si es inválida.
   385→   385→    const evento = whopsdk.webhooks.unwrap(body, { headers });
   386→   386→    
   387→   387→    if (evento.type === 'payment.succeeded') {
   388→   388→        const { id, amount_after_fees, metadata } = evento.data;
   389→   389→        const userId = metadata.user_id;
   390→   390→        const packageId = metadata.package_id;
   391→   391→        
   392→   392→        // Acreditar saldo en wallet + registrar transacción
   393→   393→        await acreditarSaldo(userId, packageId, id, amount_after_fees);
   394→   394→    }
   395→   395→    
   396→   396→    if (evento.type === 'refund.created') {
   397→   397→        // Descontar saldo si hay reembolso
   398→   398→        await reversarSaldo(evento.data);
   399→   399→    }
   400→   400→    
   401→   401→    return new Response('OK', { status: 200 });
   402→   402→}
   403→   403→```

   405→   405→### 5.3 Lógica de Débito (Express - billing.service.ts)
   406→   406→
   407→   407→```typescript
   408→   408→// Al INICIAR la llamada (evento 'start' de Twilio):
   409→   409→async function verificarSaldo(userId: string): Promise<boolean> {
   410→   410→    const { saldo } = await getWallet(userId);
   411→   411→    const limiteNegativo = await getConfig('limite_saldo_negativo'); // ej: -5.00
   412→   412→    
   413→   413→    if (saldo <= parseFloat(limiteNegativo)) {
   414→   414→        return false; // Rechazar llamada
   415→   415→    }
   416→   416→    return true; // Permitir (incluso con saldo negativo hasta el límite)
   417→   417→}
   418→   418→
   419→   419→// DURANTE la llamada (cada 60 segundos o al finalizar):
   420→   420→async function debitarLlamada(userId: string, callSid: string, duracionSegundos: number) {
   421→   421→    const cobroPorSegundo = await getConfig('cobro_por_segundo') === 'true';
   422→   422→    const precioMinuto = await getPrecioMinuto(userId);
   423→   423→    
   424→   424→    let monto: number;
   425→   425→    if (cobroPorSegundo) {
   426→   426→        const precioSegundo = precioMinuto / 60;
   427→   427→        monto = precioSegundo * duracionSegundos;
   428→   428→    } else {
   429→   429→        const minutos = Math.ceil(duracionSegundos / 60); // Redondea hacia arriba
   430→   430→        monto = precioMinuto * minutos;
   431→   431→    }
   432→   432→    
   433→   433→    // Registrar débito en wallet_transactions
   434→   434→    await registrarTransaccion(userId, 'debito', -monto, callSid, `Llamada ${callSid}`);
   435→   435→}
   436→   436→```

   438→   438→### 5.4 Notificaciones de Saldo Bajo
   439→   439→
   440→   440→- Al **50%** del saldo inicial de la última recarga → notificación in-app.
   441→   441→- Al **20%** → notificación in-app + email.
   442→   442→- Al **5%** → notificación in-app + email urgente.
   443→   443→- Al llegar a **$0.00** → email: "Tu saldo se agotó. Recarga para seguir recibiendo llamadas."

   446→   446→### 5.5 Cuando el saldo llega al límite negativo
   447→   447→

   449→   449→- Las **siguientes** llamadas reciben un TwiML con `<Say>`: *"Lo sentimos, este servicio no está disponible temporalmente."* y se cuelga.
   450→   450→- El número sigue activo pero no procesa IA.

   539→   539→### 7.2 WebSocket de Twilio → Gemini (Pipeline de Audio)
   540→   540→
   541→   541→**Eventos de Twilio entrantes**: `start`, `media`, `stop`.
   542→   542→
   543→   543→**Transcodificación Twilio → Gemini**:
   544→   544→```
   545→   545→Twilio envía: G.711 μ-law, 8kHz, mono, Base64
   546→   546→     ↓ decodificar Base64
   547→   547→     ↓ μ-law → PCM lineal 16-bit (usar paquete 'g711')
   548→   548→     ↓ resamplear 8kHz → 16kHz (usar fluent-ffmpeg o interpolación lineal)
   549→   549→Gemini espera: PCM 16-bit, 16kHz, Little-Endian
   550→   550→```
   551→   551→
   552→   552→**Transcodificación Gemini → Twilio**:
   553→   553→```
   554→   554→Gemini envía: PCM 16-bit, 24kHz, Little-Endian, Base64
   555→   555→     ↓ decodificar Base64
   556→   556→     ↓ resamplear 24kHz → 8kHz
   557→   557→     ↓ PCM lineal → μ-law (usar paquete 'g711')
   558→   558→     ↓ codificar Base64
   559→   559→Twilio espera: G.711 μ-law, 8kHz, Base64
   560→   560→```

   627→   627→### 7.5 Barge-in (Interrupción)
   628→   628→
   629→   629→**Gemini detecta la interrupción** (VAD nativo del modelo multimodal). Cuando detecta voz del usuario mientras genera audio:
   630→   630→1. Gemini **cancela** su generación actual internamente.
   631→   631→2. Deja de enviar chunks de audio por el WebSocket.
   632→   632→
   633→   633→**Tu servidor Express debe**:
   634→   634→1. Detectar que Gemini dejó de enviar audio (no hay nuevos `part.inlineData` por > 200ms mientras Twilio sigue mandando `media` inbound).
   635→   635→2. Inmediatamente enviar a Twilio:
   636→   636→```json
   637→   637→{ "event": "clear", "streamSid": "MZ..." }
   638→   638→```
   639→   639→3. Esto limpia el búfer residual de Twilio (los 1-2 segundos de audio ya encolado).
   640→   640→
   641→   641→**Filtro de ruido**: Para evitar que ruido ambiental dispare falsas interrupciones, implementar un umbral de energía en los chunks inbound de Twilio. Solo considerar "voz real" si la energía del frame supera un umbral configurable (ej: -40dBFS). Usar la librería `webrtcvad` (VAD nativo) como segundo filtro si el análisis de energía no es suficiente.
   642→   642→

   777→   777→// Evento 'stop' de Twilio
   778→   778→async function finalizarLlamada(userId: string, callSid: string, streamSid: string) {
   779→   779→    const inicio = registroLlamadas.get(callSid)?.inicio;
   780→   780→    const duracionSegundos = Math.round((Date.now() - inicio) / 1000);
   781→   781→    
   782→   782→    // 1. Debitar
   783→   783→    await debitarLlamada(userId, callSid, duracionSegundos);
   784→   784→    
   785→   785→    // 2. Grabación (si aplica)
   786→   786→    if (grabacionActiva) await ensamblarYSubirAudio(callSid, userId);
   787→   787→    
   788→   788→    // 3. Métricas
   789→   789→    await guardarMetricas(callSid, userId, duracionSegundos);
   790→   790→    
   791→   791→    // 4. Cerrar sesión Gemini
   792→   792→    await session.close();
   793→   793→    
   794→   794→    // 5. Limpiar Redis temporal
   795→   795→    await limpiarBuffersLlamada(callSid);
   796→   796→    
   797→   797→    // 6. Notificar al dueño (SSE)
   798→   798→    emitirSSE(userId, 'llamada_finalizada', { callSid, duracionSegundos });
   799→   799→}

   804→   804→## 8. SIMULADOR DE CONTEXTO (Entrevista de Voz)
   805→   805→
   806→   806→### 8.1 Flujo Completo
   807→   807→
   808→   808→1. El cliente entra a `/configuracion/contexto` (desktop) o `/mobile-configuracion/simulador` (móvil).
   809→   809→2. Ve un botón de micrófono. Al presionar:
   810→   810→   - Se abre WebSocket con Express.
   811→   811→   - Express abre sesión Gemini con `systemInstruction` de entrevistador.
   812→   812→   - **El cliente habla primero**. La IA escucha.
   813→   813→3. La IA tiene como objetivo: extraer toda la información del negocio (qué hace, servicios, precios, reglas, tono deseado, etc.).
   814→   814→4. Cuando la IA considera que tiene suficiente información, pregunta: *"¿Esto sería todo? Te doy un resumen de lo que tenemos hasta ahora."*
   815→   815→5. Si el cliente dice **"sí / está bien"** → La IA da el resumen y llama a `guardar_contexto`.
   816→   816→6. Si el cliente dice **"no, falta más"** → La IA sigue escuchando y preguntando.
   817→   817→7. **Timeout**: Si no se detecta intención real de conversación (silencio prolongado > 30s o respuestas sin sentido), la IA pregunta: *"¿Sigues ahí? Si necesitas más tiempo, puedes volver a iniciar la conversación."* Tras 60s más sin respuesta, se cierra gracefully.
   818→   818→
   819→   819→### 8.2 Edición Posterior
   820→   820→
   821→   821→- Después de la entrevista, el `raw_context` se muestra en un textarea editable.
   822→   822→- El cliente puede modificarlo manualmente y guardar.
   823→   823→- Al guardar: se re-embedda (nuevo vector 768 dims) y se actualiza en Redis cache.
   824→   824→
   825→   825→### 8.3 Re-entrevista
   826→   826→
   827→   827→- Botón "Re-entrevistar".
   828→   828→- La IA inicia diciendo: *"Ya tengo información de tu negocio: [resumen breve]. ¿Qué partes quieres actualizar o agregar? También podemos empezar desde cero si prefieres."*
   829→   829→- Si el cliente dice "empezar de cero" → se archiva la versión anterior (`status = 'archivado'`) y se crea nueva.
   830→   830→- Si dice "quiero cambiar X" → la IA solo actualiza esa parte.
   831→   831→
   832→   832→### 8.4 Versionado
   833→   833→
   834→   834→- Cada guardado incrementa `version` en `business_memory`.
   835→   835→- Las versiones anteriores quedan con `status = 'archivado'` (no se borran).

   854→   854→
   855→   855→```typescript
   856→   856→async function verificarOverlap(userId: string, startTime: Date, endTime: Date, recursoId?: string): Promise<boolean> {
   857→   857→    let query = `
   858→   858→        SELECT COUNT(*) FROM appointments 
   859→   859→        WHERE user_id = $1 
   860→   860→        AND status != 'cancelado'
   861→   861→        AND start_time < $3 
   862→   862→        AND end_time > $2
   863→   863→    `;
   864→   864→    const params: any[] = [userId, startTime, endTime];
   865→   865→    
   866→   866→    if (recursoId) {
   867→   867→        query += ` AND recurso_id = $4`;
   868→   868→        params.push(recursoId);
   869→   869→    }
   870→   870→    
   871→   871→    const { rows } = await pool.query(query, params);
   872→   872→    return parseInt(rows[0].count) > 0; // true = HAY conflicto
   873→   873→}
   874→   874→```

   876→   876→### 9.3 Horarios y Zonas Horarias
   877→   877→
   878→   878→- Todas las fechas se guardan en **UTC** (`TIMESTAMP WITH TIME ZONE`).
   879→   879→- La IA conoce la zona horaria del negocio (inyectada en system prompt).
   880→   880→- Cuando la IA dice "Tu cita es a las 3 PM", se refiere a la hora local del negocio.
   881→   881→- El frontend muestra las citas en la zona horaria del negocio (usar `date-fns-tz` o `luxon`).
   882→   882→
   883→   883→### 9.4 Modo 24/7 vs Horario Restringido
   884→   884→
   885→   885→- `modo_24_7 = true`: La IA contesta siempre. Fuera de horario: informa, ofrece tomar mensaje, pero **NO agenda**.

  1019→  1019→## 14. SEGURIDAD
  1020→  1020→
  1021→  1021→1. **Twilio**: Validar `X-Twilio-Signature` en cada webhook usando el `auth_token` de la subcuenta.
  1022→  1022→2. **Whop**: Verificación automática con `whopsdk.webhooks.unwrap()` (firma HMAC).
  1023→  1023→3. **JWT**: En todas las rutas protegidas. Expiración: 24h. Refresh token: 7 días.
  1024→  1024→4. **Encriptación**: `twilio_subaccount_auth_token` con AES-256-GCM (`crypto.createCipheriv`).
  1025→  1025→5. **CORS**: Express solo acepta requests del dominio del frontend.
  1026→  1026→6. **Rate Limiting**: 100 req/min por IP en Express y Next.js.
  1027→  1027→7. **Validación de entrada**: Zod en todos los endpoints.
  1028→  1028→8. **SQL Injection**: Siempre queries parametrizadas (`$1, $2...`).
  1029→  1029→9. **Admin**: Middleware que verifica `role = 'admin'` en el JWT.

  1129→  1129→### 16.3 Búsqueda al inicio de llamada
  1130→  1130→
  1131→  1131→```typescript
  1132→  1132→async function obtenerContextoNegocio(userId: string): Promise<string> {
  1133→  1133→    // 1. Intentar Redis (TTL 60s)
  1134→  1134→    const cached = await redis.get(`contexto:${userId}`);
  1135→  1135→    if (cached) return cached;
  1136→  1136→    
  1137→  1137→    // 2. Buscar en pgvector (por si hay múltiples fragmentos)
  1138→  1138→    const { rows } = await pool.query(`
  1139→  1139→        SELECT raw_context, 1 - (embedding <=> $2::vector) AS similitud
  1140→  1140→        FROM business_memory
  1141→  1141→        WHERE user_id = $1 AND status = 'activo'
  1142→  1142→        ORDER BY embedding <=> $2::vector
  1143→  1143→        LIMIT 3
  1144→  1144→    `, [userId, embeddingConsulta]);
  1145→  1145→    
  1146→  1146→    const contexto = rows.map(r => r.raw_context).join('\n---\n');
  1147→  1147→    
  1148→  1148→    // 3. Cachear
  1149→  1149→    await redis.setex(`contexto:${userId}`, 60, contexto);
  1150→  1150→    
  1151→  1151→    return contexto;
  1152→  1152→}
  1153→  1153→```
